### Architecture & Design

- (2026-03-14, code-review) **Inquiry vs. Directive Mandate:** NEVER modify the codebase during an Inquiry phase (e.g., /code-review). Directives for implementation must be explicitly issued by the user. Unauthorized "fixes" contaminate the research phase, bloat the context, and invalidate the review report.
- (2026-03-10, refactor_search_release_date_ui_cleanup) Movie model has no single `releaseDate` — uses `inCinemas`, `physicalRelease`, `digitalRelease`; use earliest non-null as guard.
- (2026-03-10, feature_android_push_notifications) Create `ApiEventHub` BEFORE services that need it in `main.ts` — avoids circular dependency.
- (2026-03-10, feature_system_health) `vi.hoisted()` required for mock variables inside `vi.mock()` factories.

### Recurring Gotchas

- (2026-03-10, refactor_search_release_date_ui_cleanup) Write tool requires the file to have been Read in the current session before editing.
- (2026-03-12, chore_import_cleanup) When fixing a null-guard bug in one path, check all sibling paths for the same pattern (ImportManager had identical fall-through in both episode and movie paths).
- (2026-03-13, chore_seeding_protector_wiring) After adding a service, verify it is wired in `main.ts` — a never-instantiated service is dead code regardless of test coverage.
- (2026-03-13, bug_import_manager_corner_cases) Before a for-loop over a possibly-empty collection, guard with `if (items.length === 0)` and emit a failure event — zero iterations are silent no-ops.
- (2026-03-13, bug_search_aggregation_corner_cases) Validation guards that must NOT emit failure events must be placed **before** the `try/catch` block — a guard throw inside try is caught, re-wrapped with a misleading "handoff failed" prefix, and triggers a spurious failure event.
- (2026-03-13, bug_rss_media_monitor_corner_cases) Services that grab torrents must pass `episodeId`/`movieId` to `addTorrent` — omitting them breaks the ImportManager fast-path for all RSS-triggered downloads. Audit every `addTorrent` call to confirm media context is forwarded.
- (2026-03-14, chore_shadcn_setup) Radix `Tooltip` **requires** `TooltipProvider` as an ancestor — wire it in `AppProviders` at app root and use a `renderWithTooltip()` helper in tests for all components that contain a `Tooltip`.
- (2026-03-15, chore_server_module_alignment) For tsx/transpiler-based servers, use `"module": "preserve"` + `"moduleResolution": "bundler"` in tsconfig — NOT `module:nodenext`. The latter requires `.js` extensions on all relative imports (622 TS2835 errors) and conflicts with `type:commonjs` in package.json. `bundler` mode works with ESM-syntax source without enforcing file extensions.
- (2026-03-15, chore_server_module_alignment) Vitest mocks must match the import style in the source: if source uses named imports (`import { validate } from 'node-cron'`), the mock must export `{ validate: ... }` — NOT `{ default: { validate: ... } }`. Changing from default to named imports breaks any test that mocks via `default:`.
- (2026-03-15, bug_torrent_manager_corner_cases) `vi.fn(() => impl)` uses an arrow function internally; `new vi.fn()` fails with "is not a constructor". Use `vi.fn(function() { return impl; })` for mocks that will be called with `new`. Vitest warns about this at test run time.
- (2026-03-15, bug_torrent_manager_corner_cases) `vi.clearAllMocks()` only clears call history — it does NOT clear `mockReturnValue`/`mockResolvedValue` implementations. Use `vi.resetAllMocks()` in `afterEach` (clears implementations) + `beforeEach` to restore hoisted mock defaults. This prevents cross-test contamination when one test sets a return value that a later test relies on being absent.
- (2026-03-16, bug_autosearch_all_corner_cases) Fire-and-forget methods with `setTimeout` delays require `vi.useFakeTimers()` + repeated microtask flushes (flush → advanceTimers → flush). Background loop services need `private isRunning = false` guard + `finally` reset — without it every interval tick causes duplicate grabs.
- (2026-03-16, bug_series_routes_import_rescan) When a route uses `prisma.X.upsert`, always include the owning FK (`seriesId`, `userId`, etc.) in the **update** clause as well as the **create** clause. Omitting it from update means a re-entrant upsert (rescanning a series) silently leaves the FK stale, enabling cross-series record contamination. The `import/apply` route (file-move + DB variant create) is a 5th import path separate from `ImportManager` — treat it as a first-class import path with the same error-handling discipline (failed++ per item, never early-return from the batch).
- (2026-03-18, feature_ai_release_parser) **READ AND FOLLOW THE SPEC. When the spec says replace X with Y, that means X is gone.** Repetition from user means you failed — stop and re-read the spec before writing more code.
- (2026-03-30, chore_drizzle_migration) **Drizzle SQLite gotchas:** `integer()` has no `mode: "bigint"` (use plain `integer()`); `onDelete` actions are lowercase (`"cascade"` not `"CASCADE"`); `drizzle-kit generate` crashes on `0n` defaults (use `sql\`0\``); migration pattern: `PrismaClient`→`DB`, `findUnique`→`select().where().limit(1)`, `upsert`→check+insert.
- (2026-03-31, bug_corner_case_testing) **`if (!parsed)` guard prevents episode-to-movie fallback.** ImportManager's slow path parses the filename as an episode. If the episode doesn't exist in the DB, the code should fall through to try movie matching. But the movie path is guarded by `if (!parsed)` (line 439), so parsed-but-unmatched episodes always go to "no match found" instead. Fix: track the "no episode found" condition and use it to enter the movie path.
- (2026-03-31, bug_corner_case_testing) **Testing private methods via public API.** `titlesMatch`, `isSeasonComplete`, `parseInfoHash` are private. Test them indirectly through `autoSearchEpisode`, `autoSearchSeries`, `retryImportByActivityEventId`. This ensures tests survive refactoring.
- (2026-04-02, bug_seed_limit_import_guard) **Duplicate seed-limit checking creates race conditions.** `TorrentManager.checkSeedLimits()` (every 5–30s stats sync) and `SeedingProtector.checkLimits()` (every 60s interval) both checked seed limits independently. The faster one (`TorrentManager`) deleted torrents before the slower one could apply its import guard. Fix: extract shared guard logic and apply it in both paths. When two services guard the same condition, the guard must be in the fastest path, not just the slowest.
- (2026-04-03, bug_rss_pipeline_corner_cases) **RssMediaMonitor season packs use `episodeNumbers[0]` (undefined) in DB query.** Season pack releases produce empty `episodeNumbers[]`, so `parsed.episodeNumbers[0]` is `undefined`. Prisma ignores `undefined` fields in `where`, so the query matches any monitored episode in the season. This is a design limitation, not a crash — the service is designed for single-episode RSS grabs.
- (2026-04-03, bug_rss_pipeline_corner_cases) **`vi.clearAllMocks()` clears `vi.mock()` factory implementations.** When a `vi.mock()` factory uses `vi.fn().mockImplementation(...)`, `vi.clearAllMocks()` clears the implementation, causing "is not a constructor" errors. Use class-based mocks in `vi.mock()` factories instead: `vi.mock('mod', () => ({ Cls: class { method = mockFn } }))`.
- (2026-04-03, bug_torrent_lifecycle_corner_cases) **`removeTorrent` does NOT check import guard — only `checkSeedLimits` does.** A user can manually delete a torrent (via API) whose media hasn't been imported yet, and files get deleted from disk. This is a design decision: seed-limit deletion is automatic and must be guarded, but manual removal is intentional user action. If this changes, add `isImportIncomplete()` check to `removeTorrent`.
- (2026-04-04, bug_organize_services_corner_cases) **Missing field in data-transfer objects is a silent bug.** `SeriesOrganizeService.previewRename` built a `SeriesInfo` object from the episode DB record but omitted `absoluteEpisodeNumber`, causing the `{Absolute Episode Number}` naming token to always resolve to `0`. When adding new naming tokens, always verify the DTO construction copies the source field. Test by checking token output, not just code review.
- (2026-04-04, bug_organize_rename_transaction_safety) **DB-before-fs rename pattern prevents orphaned files.** When renaming files that are tracked in the database, always update the DB path first, then perform the filesystem rename. If the fs operation fails, roll back the DB path to its original value. This ensures no partial state where the file is moved but the DB still points to the old location. The rollback try/catch must not mask the original error — catch it silently and re-throw the primary failure.
- (2026-04-04, bug_import_post_import_corner_cases) **For-loops processing independent items must have per-item try/catch.** ImportManager's `handleTorrentCompleted` iterated over torrent files, but `organizeMovieFile`/`organizeFile` throws propagated out of the loop and aborted the entire batch. Fix: wrap each iteration body in try/catch, emit per-item failure, `continue`. This pattern applies to any for-loop over a collection where items are independent (batch imports, bulk updates, notification dispatch).
- (2026-04-04, bug_import_post_import_corner_cases) **`vi.mock` with `default` export requires accessing `.default` from dynamic import.** `const mod = await import('node:fs/promises')` returns `{ default: { stat: vi.fn(), ... } }`, not `{ stat: vi.fn() }`. Access `mod.default.stat` when modifying mock behavior in tests that use `vi.mock('node:fs/promises', () => ({ default: { ... } }))`.
- (2026-04-04, bug_wantedsearch_comprehensive_corner_cases) **`autoSearchMovie` must validate release title like `autoSearchEpisode` does.** Without title validation, the indexer's movie search can return similarly-titled films (sequels, remakes) that get auto-grabbed. Use the same normalization strategy as `titlesMatch` plus year validation to reject releases with a different year.
- (2026-04-04, bug_wantedsearch_comprehensive_corner_cases) **Consistency between air-date guards is critical.** `isSeasonComplete` and `isReleasedYet` must use the same grace period — otherwise a season can be considered "complete" for pack searching while individual episodes are still skipped, causing premature pack grabs.
- (2026-04-04, bug_wantedsearch_comprehensive_corner_cases) **Multi-episode regex must capture all episode numbers.** `S(\d{1,2})E(\d{1,3})` only captures the first episode. Use `S(\d{1,2})E(\d{1,3}(?:E\d{1,3})*)` and split on 'E' to get all episodes.
- (2026-04-04, bug_searchaggregation_comprehensive_corner_cases) **`releaseParser.parseBatch` has no try/catch — AI service failure crashes the entire search pipeline.** Always wrap external service calls (AI, network, DB) in try/catch with graceful degradation. The fix: wrap the batch parsing block so Levenshtein-only scoring serves as fallback when AI is unavailable.
- (2026-04-04, bug_searchaggregation_comprehensive_corner_cases) **`toSearchCandidate` passes indexerFlags raw; normalization only happens in `toScoringCandidate`.** The `SearchCandidate.indexerFlags` is `string | undefined` (raw), while `toScoringCandidate` normalizes to `string[]` for scoring. Tests must verify the correct layer — raw flags on candidates, normalized flags in scoring.

### Patterns That Worked Well

- (2026-04-01, bug_mediasearch_corner_cases) **`deduplicateByInfoHash` ranking uses `customFormatScore` which includes confidence from Levenshtein.** Two releases with the same infoHash but different titles get different confidence scores (based on Levenshtein distance to search query). The "higher-ranked" release in dedup is determined by `compareReleasesForRanking` which checks `customFormatScore` first, then seeders. Tests comparing dedup behavior must use identical titles to isolate the seeders/size ranking dimension.
- (2026-03-16, feature_ai_parsing) Wrapping a singleton AI client in a guard (`if (!API_KEY) return null`) + TDD fallback tests lets the entire codebase degrade gracefully to regex without any code changes to callers.
- (2026-03-11, feature_system_routes_coverage) TDD on routes with in-memory state: export a proxy state object; reset it in `beforeEach`. Filter-predicate bugs only surface with coverage — write tests first.
