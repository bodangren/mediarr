## 1. Summary of changes

The track fixed 7 pre-existing Vitest timeout failures in `MediaSearchService` sibling tests caused by `vi.useFakeTimers()` freezing the real `setTimeout` used inside `searchWithTimeout`.

- Added `server/src/services/MediaSearchService.timeout.repro.test.ts` with a contract test proving `searchAllIndexers` accepts an injectable `timeoutMs` and times out quickly with real timers.
- Modified `server/src/services/MediaSearchService.ts` to accept an optional `timeoutMs` parameter on `searchAllIndexers` (defaulting to the existing `INDEXER_TIMEOUT_MS = 30000`) and threaded it through both primary and IMDB-fallback `searchWithTimeout` calls.
- Updated `MediaSearchService.enrichment.test.ts` to use `vi.useFakeTimers({ toFake: ['Date'] })` so `Date.now()` remains pinned but `setTimeout` stays real.
- Updated `MediaSearchService.cornerCases.test.ts` to use a truly hanging indexer mock and pass `timeoutMs: 10`, exercising the real timeout path.
- Left `MediaSearchService.customFormat.test.ts` unchanged (it did not use fake timers).
- Updated `measure/tech-debt.md` to mark the MediaSearchService timeout item **Resolved**.
- Updated `measure/lessons-learned.md` with the fake-timer resolution pattern.
- Archived the track directory from `measure/tracks/` to `measure/archive/` and updated `measure/tracks.md`.
