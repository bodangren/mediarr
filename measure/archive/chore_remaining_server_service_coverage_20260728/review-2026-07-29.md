## 3. Code quality

Strong work, above the bar for coverage-filler tests:

- **Every file opens with an honest scope header.** `WantedService` states outright that its 100% branch figure is vacuous (zero branches) and that its tests pin the *query contract* instead; `DataDirectoryInitializer` states it must not be counted as a closed gap; `ActivityEventEmitter` states it is a 1-branch shim. This is the opposite of coverage theatre.
- **Characterisation tests are labelled as such** with the divergence spelled out — `getCutoffUnmetEpisodes` returning the missing list, `tmdbCollectionId` computed then dropped — so a future fix must break a test deliberately.
- **Injected seams used over module mocking**, per the spec: real temp dirs in `LibraryScanner`, the existing `filesystem` adapter in `DataDirectoryInitializer`, constructor injection in `MetadataProvider`. Only `ReleaseParser` is `vi.mock`ed, correctly (the real one calls a paid LLM).
- No weak assertions (`toBeDefined`/`toBeTruthy`/`expect(true)`) anywhere in the 1,753 new lines.
- The self-reported `build(undefined)` trap — a default parameter silently supplying an API key to three "missing key" tests — is fixed and the trap written into the helper's comment.

Three concrete weaknesses:

1. **`LibraryScanner.test.ts:250` — the defect pins are silently inert as root.** `it.runIf(process.getuid() !== 0)` means the two characterisation tests for the *live Medium defect* are skipped, without noise, in any root container — which is how this repo's Docker builds run. The single most important guard in the track may never execute in CI. A root-safe variant (spy on `fs.readdir` to reject for one path only, which does not violate the "no global `node:fs` mock" rule) would restore it.
2. **Five superseded duplicates left in `tests/`.** `library-scanner.test.js`, `metadata-provider.test.js` + `-unified`, `probe-metadata-parser.test.js`, `wanted-service.test.js`, `data-directory-initializer.test.js` all still exist (~660 lines). The closeout acknowledges non-sibling coverage only for `DataDirectoryInitializer` and `MetadataGenerator` — in fact *every* target had one, which strengthens the "the row measured the wrong thing" conclusion but leaves two suites per service. `tests/library-scanner.test.js` also `vi.mock`s `node:fs/promises` globally, the exact pattern this spec forbade, so the two files now teach opposite conventions.
3. **`ActivityEventEmitter.test.ts:22` casts the event fixture `as never`**, discarding type-checking of the payload contract — the one thing `tsc` could have enforced on a shim this thin.

## 4. Risks and blockers

- **Medium, live, user-facing:** `LibraryScanner.getAllFiles` — one unreadable subdirectory rejects the whole scan, and because the walk enumerates every path before parsing any, *nothing* gets linked. A user migrating a messy library sees a silent no-op. Pinned but unfixed, and (see above) unpinned in root CI. Symlink-loop recursion in the same function is an unpinned second hazard.
- **Low:** `MetadataProvider` computes `tmdbCollectionId` and drops it in all three mappings; `SeriesSearchResult` omits `popularity` although `searchSeries` always sets it, forcing `(result as any)` in production. Both logged.
- **Low:** the `MetadataGenerator` deletion is well-justified (posters are remote TMDB URLs; `downloadPoster` had no callers; two genuine defects died with it), but it leaves `.nfo`/artwork sidecar generation entirely unimplemented — `Organizer.colocateMovieMetadata` is also never called. If any user expects Kodi/Jellyfin/Plex scraper compatibility, that gap is now less visible than before.
- **Low, pre-existing:** `tests/library-scanner.test.js` does *not* mock `ReleaseParser`, so a developer running the suite with `OPENROUTER_API_KEY` or the AI-gateway vars exported would make real paid LLM calls from a unit test. Bare runs fall back to regex (no dotenv in `vitest.config.ts`), so this is latent, not active.
- No blockers. The tree is green and the archive is consistent.
