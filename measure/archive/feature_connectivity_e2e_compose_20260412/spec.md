# Specification: Connectivity E2E Test Harness (podman compose)

## Problem

We have unit tests that mock mDNS and HTTP, and a Flutter integration test that only asserts the discovery screen renders. Nothing exercises the full client→server path end-to-end: discovery → connect → list library → stream bytes. When this path silently breaks (proxy headers, range handling, mDNS advertisement, DB schema drift) we find out from the user.

## Goal

A reproducible, user-runnable connectivity test suite under `tests/connectivity/` that:

1. Builds a server container from the current codebase (Bun + Drizzle, no Prisma, no Next.js).
2. Boots the server with a seeded SQLite DB containing one movie + one TV episode whose `hasFile=true` paths resolve to real on-disk media (generated at build time via ffmpeg).
3. Advertises `_mediarr._tcp` over mDNS on the compose network.
4. Runs a Dart CLI client that:
   - Discovers the server via real multicast DNS (`package:multicast_dns`).
   - Connects over HTTP, fetches `/api/system/status`.
   - Lists movies + series, asserts the seeded fixtures are present with expected titles/IDs.
   - Fetches playback manifest for both the movie and the episode.
   - Issues a ranged `GET /api/stream/:id?type=…` and asserts `206 Partial Content`, correct `Content-Type`, byte count.
   - Subscribes to `/api/events` (SSE), triggers a server-side event via a test endpoint, asserts delivery within a timeout.
5. Exits non-zero on any failure; prints a structured report on success.

## Non-Goals

- UI/widget testing (covered by Flutter test/ and integration_test/).
- Transcoder pipeline exercise (deferred; would require ffmpeg in the server image).
- Cross-host mDNS (same-compose-network only for Phase 1).
- Replacing the existing root `docker-compose.yml` / `Dockerfile` (which are stale; addressed in a separate track).

## Success Criteria

- `cd tests/connectivity && podman compose up --build --abort-on-container-exit --exit-code-from client-test` returns exit code 0 on a healthy build.
- Exit code is non-zero if any of: discovery times out, HTTP connect fails, listed fixtures missing, range request returns wrong bytes/status, SSE event not received.
- Readme at `tests/connectivity/README.md` tells a user how to run it with podman (and `docker compose` as a fallback).
- CI-invocable via `npm run test:connectivity` at repo root.

## Out-of-Scope Risks (noted for future tracks)

- podman rootless + multicast: some distros need `net.ipv4.ip_multicast_all=1` or a specific network backend. We document the workaround; we do not try to solve it universally.
- SSE event-trigger endpoint adds a test-only route behind `NODE_ENV === 'test'`. Not exposed in production.

## Fixtures

- `movie.mp4` and `episode.mp4`: 2-second `testsrc` patterns generated by ffmpeg in the image build (~50 KB each, deterministic). Not committed as binaries.
- Seeded rows:
  - Movie `id=1`, title `Connectivity Test Movie`, year `2026`, file at `/data/media/movies/connectivity-test-movie/Connectivity Test Movie (2026).mp4`.
  - Series `id=1`, title `Connectivity Test Series`; Season 1; Episode `S01E01` titled `Connectivity Pilot`, file at `/data/media/tv/connectivity-test-series/Season 01/Connectivity Test Series - S01E01.mp4`.

## Interface: Dart CLI

- Lives at `clients/mediarr-client/tool/connectivity_test/` — a standalone Dart package (not Flutter) so it runs in a slim Dart SDK container.
- Reuses HTTP model logic only where possible; uses `package:multicast_dns` instead of Bonsoir (pure-Dart, runs outside Flutter).
- Single entry point: `dart run tool/connectivity_test/bin/run.dart` with env-driven config (`MEDIARR_MDNS_TIMEOUT_SECS`, `MEDIARR_DIRECT_URL` for debugging).
