The new `toggleEnabled()` only mutates the in-memory `ScheduledJob.enabled` flag; it does not persist to `AppSettings` (despite the `drizzle/0003_workable_sage.sql` migration adding a `schedulerEnabled` column). Toggle state will therefore revert on process restart.

## Code quality observations
- Strong type coupling: the server exports `SchedulerTaskStatus` and `SCHEDULER_TASK_STATUS_VALUES`, and the client imports the constant instead of duplicating the literal enum. This satisfies the test-strategy §3 drift contract.
- The Fastify route and MSW handler now share the same validation/error-envelope shape, improving parity between tests and production.
- One test assertion in `schedulerApi.contract.test.ts` was relaxed from requiring a hardcoded `z.enum([...])` literal to accepting any `z.enum(` form; this was necessary because the new `schedulerApi.statusEnum.test.ts` explicitly forbids the literal. The change is justified by the spec.
- The `toggleEnabled` implementation is minimal and safe (throws on unknown job, sets boolean), but it leaves the persistence contract unfulfilled.
