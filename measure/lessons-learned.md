## Lessons Learned

### Architecture & Design

- (2026-04-24, chore_test_quality_strengthening) **React test ergonomics, three rules:** DOM node identity (`toBe`) does not verify memoization — use render-count instrumentation with `React.memo`-wrapped spy components. Radix Dialog backdrop clicks need `userEvent.click(overlay)`, not `fireEvent.click`, which fails silently. Async component tests need `act()` around both renders and event fires (FilesystemBrowser's `useEffect` + API calls warn otherwise).
- (2026-07-28, bug_ai_release_parser_lockdown_20260728) **A timeout shorter than the work is a silent no-op, and a silent fallback hides it forever.** The AI release parser had never worked as shipped: the default model measured 77–88s per call against 15s/20s abort deadlines, so every call aborted, `parse()` returned regex and `parseBatch()` returned `[]` — with nothing in the logs. Three lessons. **(a) Measure latency against the deadline, not in isolation** — "the model works" and "the model works inside 15s" are different claims, and only the second one ships. **(b) Every silent fallback needs a loud signal**; the fix was not just a faster model but a warning when the configured model is unmeasured, because the next operator override can reintroduce the defect. **(c) Never zip two arrays by position when one came from an LLM.** `parseBatch` results were assigned to releases by index; cheap models truncate (observed 7-of-8 and 6-of-8 live), which shifts every later parse onto the wrong release — and that score drives auto-grab, so the failure mode was downloading the wrong thing. Make the model echo an id and match on it; leave unmatched slots empty. Fail-soft on the instruction, fail-closed on the attribution. Notably `parseFiles()` in the same file already had the length guard `parseBatch()` lacked — **when fixing a defect, check whether a sibling function already solved it.**
- (2026-04-24, chore_lint_debt_reduction) **File-level `eslint-disable` is acceptable for framework-level mismatches.** 10 files exported both components and helpers; disabling `react-refresh/only-export-components` per-file is safer than risky refactors. Prefer block-level disables for rule-of-thumb exceptions like `react-hooks/set-state-in-effect`.
- (2026-07-27, database_migration_strategy_20260713) **Drizzle SQLite gotchas and safe migrations:** `integer()` has no `mode: "bigint"`; `onDelete` is lowercase; avoid `0n` defaults. `PRAGMA foreign_keys=OFF` is a **no-op inside a transaction**, and `drizzle-kit migrate` wraps every pending migration in one — so a parent-table rebuild cascade-deletes children *and still commits successfully*. Noting the hazard (2026-07-24) was not enough; the migration path kept using `drizzle-kit migrate` for three more days. Fixed by owning application in `server/src/db/migrationRunner.ts`: pragma outside the transaction, one transaction per migration, `PRAGMA foreign_key_check` before each commit. **A hazard recorded in memory but left wired into the entrypoint is not mitigated.**
- (2026-04-09, chore_drizzle_migration) **Avoid static Bun-only imports in Node-compatible code paths.** `drizzle-orm/bun-sqlite` eagerly requires `bun:sqlite`; load Bun/Node adapters lazily via `createRequire` runtime detection.
- (2026-04-09, chore_drizzle_migration) **Bun + WebTorrent native addons can hard-crash on hosts missing libuv/N-API coverage.** Launch daemon with `bun --no-addons` to disable addon loading and allow graceful fallback manager startup.
- (2026-04-09, feature_playback_resume_sync) **Router-level Flutter widget tests must override every network-backed provider used by shell screens.** New top sections (like continue-watching) can trigger unmocked Dio calls and pending discovery timers unless explicitly overridden in `app_router_test.dart`.
- (2026-04-09, feature_notification_transports) **Treat `CI=true npm test` as the authoritative suite in this repo.** `bun test` is useful for spot checks but can hang/fail on Vitest-specific semantics; keep Bun-runner deviations explicit in track metadata.
- (2026-07-27, chore_home_network_deployment_hardening) **An intermittent failure needs repeated runs before you call it fixed, and a control arm before you call it diagnosed.** The clean-image `Rollup failed to resolve import "<dep>" from "/app/app/..."` defect names a different module each run. A probe *inside the failing build layer* settled what it is not: immediately before rollup and again after it fails, all 47 app deps resolve from `/app/app` and all 37 `@radix-ui` packages are complete; `tsc -b` passes on the same specifier seconds earlier. The files are present and resolvable — so the **"overlay write-visibility" explanation previously recorded here was wrong**, as were missing-dependency, npm-flag, fd-exhaustion, and disk-pressure. Node 22 and npm 10.9.8 each *looked* like the fix until a control arm — same added layer, stock Node 20 + npm 10.8.2 — went 3/3 green, showing the added layer, not the version, tracked the outcome. Four process lessons: **probe before adopting a workaround**; **a structural test that pins the current Dockerfile shape locks in the bug** (assert the invariant, not the status quo); **when an experiment adds a variable, add a control that changes nothing else** — every green arm measured before that control was uninterpretable; and, once a defect stops reproducing on demand, **stop running arms and make the build self-diagnosing instead** (2026-07-28: `scripts/docker-build-spa.sh` re-runs a failed SPA build under `DEBUG=vite:resolve`). Two hazards when doing that: such a wrapper **must exit with the original status, never the retry's**, or it silently converts an intermittent failure into a pass; and a multi-minute `docker build` belongs behind an env gate (`CLEAN_IMAGE_BUILD_TESTS`), not inside `vitest run`. It paid off on its first live failure and produced the lesson that outranks all the above: **measure a limit in the namespace that actually runs the code.** `ulimit -n` is **1024/1024 inside a buildah `RUN` layer** but 1048576 under `podman run` and on the host — so the earlier "fd exhaustion excluded" was a correct reading of the wrong context, and cost a week. A two-line Dockerfile settles it in 20 seconds; `podman run`, `docker exec`, and a host shell are all different namespaces from the build.

### Patterns That Worked Well

- (2026-04-05, bug_pipeline_integration_corner_cases) **Integration tests across service boundaries catch data-flow bugs.** Use event-emitter mocks with manual `emit()` + microtask flush.
- (2026-04-08, chore_form_standardization_completion) **useFieldArray return value is NOT stable** — do NOT put `dynamicFieldArray` from `useFieldArray` in useEffect dependency arrays; causes infinite loops. Only put primitive dependencies like `selectedPreset`.
- (2026-04-08, chore_form_standardization_completion) **Don't use explicit `id` on Radix SelectTrigger inside FormField** — FormLabel's `htmlFor` is auto-generated, conflicting with explicit `id="edit-indexer-protocol"`. NumberInput needs explicit id since it's not a Radix component.
- (2026-04-08, chore_form_standardization_completion) **`form.formState.isValid` starts false despite valid defaultValues** — use computed `canSave` from actual form values instead of `isValid` to enable save button. `isValid` only updates after validation runs, not on form reset.
- (2026-04-16, feature_flutter_search_add) **`StateProvider.overrideWith` factory returns the state directly** — use `overrideWith((ref) => 'value')`, NOT `ref.state = 'value'; return 'value';`. The `ref` inside override is an `OverrideRef`, not a `StateProviderRef`.
- (2026-04-17, feature_flutter_activity_queue) **Flutter mock class must implement ALL interface methods** — Adding new methods to `MediarrApiClient` breaks any `_MockMediarrApiClient` that uses `implements`. Must add empty implementations for `getTorrents`, `getActivity`, `pauseTorrent`, `resumeTorrent`, `removeTorrent`.
- (2026-07-24, bug_server_integrity_remediation_20260724) **Quality-profile resolution must fail closed.** Strictly reject unknown requested IDs; when no ID is requested, require the configured named default to exist. Never fall back to the first row or a literal ID, because that silently assigns the wrong policy or causes FK failures.
- (2026-04-23, bug_manual_test_player_client_findings) **SSE event contracts need explicit documentation.** Server and client must agree on event names (e.g., 'torrent:stats' not 'torrent:progress'). Add regression tests to prevent drift.
- (2026-04-23, bug_manual_test_player_client_findings) **Player-first navigation requires explicit product decision.** Admin surfaces (Activity, Search) should not be default routes. Home/Continue Watching should be the primary entry point for a media player client.
- (2026-07-27, measure_orchestration) **Verify claims against source — specs, code comments, and test *names* all lie.** Three failure modes seen: (a) specs describing code that does not exist (`filter_service_test_coverage` specified filters `FilterService` never had; `settings_and_tvsearch_test_coverage` specified `TvSearchService`, deleted six weeks earlier); (b) a code comment asserting a missing dependency — Flutter's movie Delete was a no-op "until the server exposes a DELETE endpoint" that had existed all along; (c) **a test whose title and `reason` claimed it verified an API call "fires exactly once" while its only assertion was that a dialog closed** — it passed green against `onPressed: () {}`. Grep every named symbol, and read a test's *assertions*, never its name. A task marked "human-gated" can be hiding unimplemented work.
- (2026-07-27, measure_orchestration) **Re-derive the backlog from the build, and re-run the gates before recording them as green.** Seven app tracks carrying ~106 "open" tasks were already satisfied upstream; one `npm test` + `tsc --noEmit` turned ~200 phantom tasks into a doc reconciliation. But the 2026-07-26 commit that recorded "SPA 204 files / 1960 passed / 0 failures" **also pruned the tech-debt row that `app/src/lib/msw/handlers.s6.test.ts` asserted on**, so it broke the SPA suite in the same commit that declared it green. Two rules: run the gates *after* the last edit, not before; and **never let a product test assert on curated project docs** — `tech-debt.md` explicitly instructs pruning of resolved rows, so a track-closure check pinned to its contents is a time bomb that fires on the next cleanup.
- (2026-07-26, settings_and_tvsearch_test_coverage) **A branch-coverage target on a pass-through wrapper is unfalsifiable.** `SettingsService.ts` is a 3-method delegation to `AppSettingsRepository` with zero branches, so "≥80% branch coverage" was satisfied at 0 tests. When setting coverage goals, target the layer that actually holds the conditionals — here `AppSettingsRepository.ts` (582 LOC, ~34 branch points).
- (2026-07-26, measure_orchestration) **Parallel subagents need disjoint file ownership and a single committer.** Four agents ran concurrently on one worktree with zero collisions by giving each agent its own service test files plus its own track docs, while the orchestrator retained `tracks.md`, `tech-debt.md`, `lessons-learned.md`, and every git write. Agents that share a worktree must never run `git add`/`commit`, and must never run the full suite while siblings are editing.
- (2026-05-01, feature_flutter_subtitle_quality) **Flutter detail screens should use ConsumerStatefulWidget for async sections.** Converting MovieDetailScreen from ConsumerWidget to ConsumerStatefulWidget allows subtitle inventory to load on mount without blocking the main UI. Stateful local loading keeps the scaffold responsive while async data populates.
- (2026-05-01, feature_flutter_subtitle_quality) **Reusable bottom sheet pattern with callback refresh keeps detail screens in sync.** SubtitleSearchSheet and QualityUpgradeSheet both accept `onDownloaded`/`onGrabbed` callbacks that trigger parent reload. This avoids provider complexity for one-off modal flows.
- (2026-05-05, webtorrent_download_management) **Enhance existing pages before creating new ones.** The ActivityQueuePage already had core torrent management; adding sort/filter/search/SSE/priority to it was faster and more maintainable than building separate DownloadList/TorrentRow components. Reuse existing DataTable and API patterns.
- (2026-05-06, dashboard_statistics) **Integration tests using `createApiServer` verify end-to-end route wiring.** Mocking prisma at the API server level tests the full request/response cycle including Fastify route registration, error handling, and JSON serialization. Two integration tests replaced the need for a full browser smoke test when browser-harness was unavailable.
- (2026-06-19, feature_scheduler_automation_dashboard) **Cron validation parity + hot-reload pattern:** Backend node-cron validate and frontend CronIntervalPicker share the same library; Scheduler.reschedule stops old + schedules new with no-op early-return on same expression, triggered by PUT /api/scheduler/:taskId/interval.
- (2026-07-04, bug_app_modal_close_behavior_20260703) **Radix Dialog test ergonomics:** Radix `useEscapeKeydown` listens on `document` in capture phase, so `fireEvent.keyDown(window, ...)` never triggers `onOpenChange` in jsdom. Add a bubble-phase `window` listener for tests (bail on `defaultPrevented` to avoid double-firing), and expose `data-testid="modal-backdrop"` + an overlay `onClick` fallback so `fireEvent.click(backdrop)` works alongside Radix's `pointerdown` dismissal.
### Shared Type Contracts

- (2026-05-26, chore_type_contract_sharing) **Zod schemas as shared contracts prevent server/app type drift.** Extract duplicate interfaces to `server/src/contracts/*.ts` with Zod schemas. App imports via `@server/contracts/*` alias (configured in tsconfig.app.json and vite.config.ts). Server-specific fields (Buffer, File) extend the shared base type. Changes to shared schema cause compile errors in both workspaces.
- (2026-06-07, bug_variant_subtitle_test_coverage) **Measure workflow + SubtitleVariantRepository mock patterns:** (a) Clean the tree first — run `git status` before any work and `git checkout --` pre-existing drift; skip full-project tsc (~108s, exit 124 under supervisor) in per-task attempts, trusting per-file diagnostics + targeted vitest run. (b) Mock SubtitleVariantRepository with `vi.hoisted()` factory, `vi.mock(...)` with `fn().mockImplementation(() => mock)`, mocking only the 2–6 methods each service calls.
- (2026-06-08, chore_close_drizzle_migration_20260607) **Drizzle mock-naming convention:** after the Prisma→Drizzle migration, rename all Prisma-named test helpers (`createPrismaMock→createDbMock`, `createMockPrisma→createMockDb`, `makePrisma→makeDb`, `makeMoviePrisma→makeMovieDb`) across test files. The old names cause false-positive grep hits during migration closeout and confuse new contributors. 30 test files, 4 helper names, 278 total occurrences renamed in S5.
- (2026-06-12, chore_test_infrastructure_hardening_20260612) **MSW `setupServer` can hang/leak handles with Vitest's default threads pool; prefer prop injection over `vi.mock`.** Switch to `pool: 'forks'` (or isolate the server per file); raise `testTimeout` for modal/user-event suites; pair with `userEvent.setup({ delay: null })`. Passing callbacks (e.g., `searchMovies`) as props removes per-file API mocks and keeps tests deterministic when run together.
- (2026-06-13, chore_untested_server_services_20260526) **Scheduler mock patterns + vi.useFakeTimers caveat:** `vi.mock('node-cron')` with `vi.hoisted()` exposing scheduleMock/validateMock + tasks[] registry; schedule returns `{ stop: vi.fn() }`; clear tasks in beforeEach. **`vi.useFakeTimers()` blocks `setTimeout`-wrapped indexer timeouts** (e.g., `MediaSearchService.searchWithTimeout` with `INDEXER_TIMEOUT_MS = 30000`). Fix in `bug_mediasearch_timeout_tests_20260630`: expose an optional `timeoutMs` on `searchAllIndexers` for tests, use `vi.useFakeTimers({ toFake: ['Date'] })` when only `Date.now()` needs pinning, and run timeout assertions with real timers + a short injected timeout.
- (2026-07-27, database_migration_strategy_20260713) **`scripts/` cannot statically import from `server/`.** Root tsconfig is `module: nodenext`, `server/` is `module: preserve`; a static named import across that boundary yields a default-only CJS namespace and dies at load with *"does not provide an export named …"*. It had silently broken `reconcile-migration-compatibility.ts`, so the documented `npm run migrate` could not run at all on Node 22. Use dynamic `import()` in `scripts/`, and always execute a new script once — a passing typecheck proves nothing here.
- (2026-07-03, chore_app_pre_existing_failures_20260630) **Umbrella cleanup tracks with >100 failures should be split after initial cataloging.** Fixing typecheck errors and the most obvious runtime guards first quickly narrows the failure surface; the remaining failures then cluster by root cause (modal wiring, API drift, validation UI, view props). Smaller tracks are easier to validate and less likely to time out during full-suite runs.
- (2026-06-29, scheduler_persistence_missed_task_recovery) **Scheduler durability pattern:** keep Scheduler DB-agnostic with injected AppSettings-backed state; persist nextRun on schedule/reschedule/execute, clear on stop, and call `start()` after registration for one missed run per task. Health endpoints expose live state additively.
- (2026-06-20, release_v1_cut_20260607) **Release-Cut Retrospective:** The open-ended testing tail cost ~2 weeks of continuous corner-case testing across 12+ subsystems; while the suite found 7 bugs, the diminishing-returns churn delayed the highest user-facing value tracks (Scheduler dashboard, Flutter media detail). The value-first reordering — cutting remaining untested services to post-v1.0 and shipping the scheduler + Flutter detail as v1.0 gate features — recovered delivery momentum. For future cuts: ship value over coverage, draw a hard line at the stated scope, and defer exhaustive testing to post-release.
