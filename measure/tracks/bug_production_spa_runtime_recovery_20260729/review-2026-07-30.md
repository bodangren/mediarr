## Summary of changes

The core fix for this track is commit `8a619bc` — `fix(app): keep scheduler runtime out of browser bundle`.

What changed outside `measure/`:

- **`server/src/contracts/scheduler.ts`** (new): dependency-neutral contract that owns the closed scheduler task-status union (`healthy`, `warning`, `error`, `disabled`) and its runtime values.
- **`server/src/services/Scheduler.ts`**: imports the type from the contract and re-exports it for server compatibility; keeps all `node-cron` scheduling logic unchanged.
- **`app/src/lib/api/schedulerApi.ts`**: now imports `SCHEDULER_TASK_STATUS_VALUES` / `SchedulerTaskStatus` from `@server/contracts/scheduler` instead of from the server `Scheduler` service, removing the path that pulled `node-cron` into the browser bundle.
- **`app/src/lib/api/schedulerApi.statusEnum.test.ts`**: rewritten as a contract regression that asserts the shared contract is dependency-neutral, both sides consume it, and the browser client never imports `services/Scheduler` or `node-cron`.
- **`tests/production-spa-render.test.js`** (new): production browser gate. Builds `app/dist`, serves it through the real `registerStaticServing` path, opens the configured Dashboard in Chromium, and fails on an empty `#root`, page/console errors, failed requests, or non-API HTTP failures.
- **`README.md`**: added a "Production browser gate" section documenting the new release-verification command.

Track metadata/plan/spec were also created and updated (commit `201011d2`), marking Phase 1 complete and recording the verification evidence.

Other commits in the last 24 hours (notifications, Jellyfin surface, browser-verified web-app track) are outside the scope of this bug track and are not evaluated here, except where they affect shared acceptance gates.

## Code quality observations

- **Contract boundary is clean.** `server/src/contracts/scheduler.ts` is tiny, has zero runtime dependencies, and is the single source of truth for the status union.
- **Test design is appropriate.** The production gate uses the real `registerStaticServing` path, stubs the API so the shell can settle deterministically, and captures page errors, console errors, request failures, and non-API HTTP failures.
- **Route ordering in the gate is correct.** Specific stubs (`/api/setup/status`, `/api/events/stream`) are registered before the catch-all `app.all('/api/*', ...)`, so they are not shadowed.
- **README is useful but incomplete.** It tells maintainers to run `CI=true npx vitest run tests/production-spa-render.test.js`, but a root script (e.g. `test:production-spa`) would make the gate more discoverable. It also does not mention the Playwright browser dependency.
- **Plan/tracking mismatch.** The plan lists a separate Phase 2 commit `test(app): require production SPA render before release`; in practice the test landed inside the fix commit `8a619bc`. The plan should be updated to reflect the actual commit structure.

## Risks or blockers

1. **Server typecheck is red.** `npm run typecheck --workspace=server` fails on `BrowserAcceptanceAcquisitionFixture.ts`, `BrowserAcceptanceMetadataProvider.ts`, and `main.ts` with `exactOptionalPropertyTypes` errors. These files were not touched by the scheduler fix, but they block the track's acceptance criterion that "the server typecheck pass." They must be triaged before this track can be considered closed.
2. **Playwright dependency in CI.** The production gate requires a Chromium installation. CI runners will need `npx playwright install chromium` or a system Chrome; the README does not document this.
3. **No bundle-level assertion.** The current verification relies on source-level regex checks and the runtime gate. That is sufficient in practice, but a build-artifact scan for `node-cron` would make the guarantee more explicit.
4. **Phase 3 closeout is pending.** Recording the false-green mechanism and archiving the track are still open in the plan.
