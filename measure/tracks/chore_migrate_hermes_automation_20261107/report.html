Why this exists

measured, not assumed

Three facts from the live install changed the design. None of them came from documentation — each was measured against the running system.

42 / 167
Hermes runs failed silently

Every failure was the same provider outage. Nothing noticed: no alert, no counter, no dead-man switch. 25 % of runs disappeared.

Oct 20
Last daily report artifact

The nightly YYYY-MM-DD.md stops at 2026-10-20 — yet media-orchestrator logged “completed” runs on 2026-11-06. A success status is not proof.

TV + MOVIE
Mediarr media model

Music and adult have no domain in Mediarr. The old jobs also reached into jellyfin-go over HTTP and its SQLite database — both going away.

Also true right now: the media server (Mediarr) is not installed as a service and is not running; the DSH host is a terminal-launched process with no systemd unit; and the old jobs are still enabled. Deployment, not scheduling, is the current weakest link.

How failure becomes visible

“never silently wrong”

A scheduled task's delivery receipt proves only that a message reached an inbox — not that the work succeeded. The plugin and an external watchdog close that gap from two directions.

1

DSH delivers

Weekly task fires; inbox + receipt. Provider not involved yet.

2

Agent turn runs

If the provider is down, the turn fails — durable turn/end error.

3

Plugin observes

Correlates the delivery message id with the turn outcome; writes the ledger.

4

Retry or alert

Transient → up to 2 retries. Persistent → webhook alert. No model on this path.

Plugin media-automation

  • Owns deterministic timers, the run ledger, quarantine, receipts and alerts.
  • Durable state only — safe to hot-reload or crash mid-run.
  • Retries transient failures; escalates auth/config errors immediately.
  • Writes a heartbeat every minute.

External watchdog systemd timer, 10 min

  • Runs even when the DSH host or the plugin is dead — the one failure a plugin cannot report.
  • Checks host active, heartbeat fresh, Mediarr health, expected artifacts, failed tasks.
  • One throttled webhook per incident; local fallback.
Definition of error-free: every expected occurrence either succeeded, was retried, or produced an alert. “Always succeeds” is impossible with a provider that can be down; “never silent” is achievable and is the acceptance test for the one clean week.

Guardrails & risks

what could bite
“More work into DSH” has a hard limit. Deterministic work must be plugin code. Hourly/daily model turns would restore the exact pattern that produced 42 silent failures — if that is what was meant, it must be re-decided explicitly.
DSH host is now on the critical path. All household automation depends on it. Mitigations: systemd Restart=always, durable plugin state, independent watchdog. A host that is up but whose plugin is disabled is caught by the heartbeat check.
Quarantine-then-delete is destructive. 14-day retention, manifest, restore path, safety rails, byte cap, and a dry-run week are not optional. Any delete without a manifest is a bug.
Dropping the browser removes discovery. TPB/YTS/EZTV content that no configured indexer carries is no longer discoverable. This is the accepted cost of removing Chrome + VPN from the runtime.
Full-access host. DSH_PERMISSION_MODE=danger-full-access on a trusted single-user LAN; it is required because scheduled turns cannot answer approval prompts. Documented and reversible.
Music is not solved here. Scope only. Until the new track lands, music is manual and the old job stays disabled — not deleted.
