## Summary of Changes

The track adds a complete Jellyfin-compatible server surface to Mediarr. Over the last 24 hours the implementation grew from the initial compatibility skeleton to the full reference-surface parity requested by the owner.

Key deliverables:

- **UDP discovery responder** (`server/src/services/JellyfinDiscoveryService.ts`) listens on `0.0.0.0:7359` and replies to `Who is JellyfinServer?` with the LAN-reachable address, stable server GUID, and name.
- **Server identity** (`server/src/jellyfin/serverIdentity.ts`) persists a stable GUID in `/config/jellyfin-server-id` and resolves the LAN IP while excluding loopback/container addresses.
- **Reference route surface** (`server/src/api/createJellyfinServer.ts`, `server/src/jellyfin/referenceSurface.ts`) declares every route from the working `serve.py` reference: system/handshake, users/auth, views, items, shows/seasons/episodes, images, playback info, video/audio/download streams, sessions, resume, played items, and browser entry aliases.
- **Catalog adapter** (`server/src/jellyfin/catalog.ts`, `server/src/jellyfin/prismaCatalog.ts`) maps Mediarr's movie/TV data to Jellyfin-shaped DTOs with stable GUID-like item IDs.
- **Playback adapter** (`server/src/jellyfin/playback.ts`, `server/src/jellyfin/playbackState.ts`, `server/src/jellyfin/prismaPlaybackState.ts`) provides direct-play `MediaSource`, stream serving, session endpoints, and **shared** resume/watched state through the existing `PlaybackService.recordHeartbeat` / `getContinueWatching` store.
- **Artwork proxy** (`server/src/jellyfin/artwork.ts`) allowlists and proxies remote TMDB poster/backdrop URLs so clients that do not follow redirects still receive images.
- **Configuration seam** (`server/src/config/jellyfin.ts`) exposes `JELLYFIN_ENABLED` and `JELLYFIN_PORT` so the listener can coexist with the owner's `thaidub-serve.service` on port 8096.
- **Runbook** (`docs/jellyfin-compatibility-runbook.md`) documents activation, network requirements, rollback, and the exact ThaiDub restore command.

Diff footprint: **28 files, +4,700 lines** in the Jellyfin module, discovery service, config, and runbook.

## Code Quality Observations

- **Stable identity:** Item IDs and the server GUID are deterministic and persisted; no database migration is required.
- **Single playback store:** Resume/watched state is not duplicated. The Jellyfin surface writes through `PlaybackService.recordHeartbeat` and reads through `getContinueWatching`, which is the same store the SPA uses.
- **Range streaming reuse:** `/Videos/{id}/stream` uses the shared `byteRangeStreaming` utility, satisfying the plan's requirement to avoid a second Range parser.
- **Test coverage:** The Jellyfin module has dedicated unit and integration tests for discovery, identity, DTOs, catalog, artwork, playback, sessions, playback state, and cross-surface parity. The full suite result is **346 test files passed, 1 skipped; 3045 tests passed, 14 skipped**.
- **Type safety:** Only one `as any` cast was found in the Jellyfin surface (`createJellyfinServer.ts:144`, used to access Prisma model delegates from a typed dependency bag). No `@ts-ignore` or `@ts-expect-error` suppressions were found in `server/src/jellyfin`.
- **Whitelisting:** The artwork proxy is allowlist-based and rejects arbitrary external URLs.
