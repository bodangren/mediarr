## 4. Risks or blockers

- **Phase 4 implementation is the current blocker.** Without `Scheduler.setTaskExecutionsRepository`, `triggerTask`, `pruneTaskExecutions`, and the wrap-with-recording callback, the manual-trigger and execution-history features will not actually record or clean up executions in production.
- **Trigger route is still fire-and-forget.** The plan notes that `POST /api/scheduler/:taskId/trigger` currently calls `scheduler.runNow(taskId).catch(() => {})`; it must be updated to `await scheduler.triggerTask(taskId)` so the route returns the real execution status.
- **Repository wiring at bootstrap must happen.** `createApiServer.ts` needs to construct and inject the `taskExecutionsRepository` into the scheduler instance before routes are registered.
- **App build/typecheck debt is external but visible.** Pre-existing errors in `ImportListSettings.tsx`, `msw/factories.ts`, and `msw/handlers/helpers.ts` block a clean app build. These are not caused by this track, but they prevent closing the "build clean" acceptance criterion.
